The key pin

The program trusts the server only if its public key matches a key pin in Settings. A pin is the base64 SHA-256 hash of the key: 44 characters ending in =, for example

Example0Example0Example0Example0Example0Ex0=

(an example, not the real pin). It does not use any certificate authority, so Let's Encrypt renewals make no difference as long as the server keeps the same key. See How the connection is secured.

Getting the pin from the server

Settings > Server > Get pin from server... connects to the host and port you entered and shows the key the server presented: its pin, key type, the names on its certificate, issuer and dates.

This pin has NOT been verified. It is whatever answered the connection. If something is intercepting the connection, it is the interceptor's key. The program adds the pin only after you tick I have checked this pin against a trusted source and it matches, and warns in red if it differs from the pins you already have.

A key that changed when you did not expect it to is a reason to stop and find out why, not to add the new pin. If the pin is already in your list, the program says so and there is nothing to do.

Checking the pin

Compare the pin character by character with one from a source you trust. The most direct is the key file on the server itself (OpenSSL or LibreSSL), from the key the server uses:

openssl pkey -in /etc/ssl/private/pastes.glitchwrks.com.key -pubout -outform der \
  | openssl dgst -sha256 -binary | openssl base64

From another machine you trust, you can also ask the server over the network. Like Get pin from server, this only reports what answered, so it is a check from a different vantage point, not proof:

openssl s_client -connect pastes.glitchwrks.com:443 -servername pastes.glitchwrks.com </dev/null 2>/dev/null \
  | openssl x509 -pubkey -noout \
  | openssl pkey -pubin -outform der \
  | openssl dgst -sha256 -binary \
  | openssl base64

Backup pins

Put each pin on its own line. A second pin for a backup key lets the server switch to that key without every client needing an update.

If the key does not match

Sending fails with Server key mismatch and nothing is sent. See If something goes wrong.
