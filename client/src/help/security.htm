How the connection is secured

Java 5's own encryption support stops at TLS 1.0 and trusts a list of certificate authorities from 2009, so a modern server cannot be reached with it. gw_paste98 carries its own:

  • TLS 1.2 from Bouncy Castle. The encryption code is built into GWPASTE.JAR, so Java 5's outdated TLS support and certificate list are not used at all.
  • A pinned server key instead of certificate authorities. The program talks only to a server whose public key matches one of the key pins in Settings. Let's Encrypt certificate renewals make no difference, as long as the server keeps the same key.
  • Modern ciphers. ChaCha20-Poly1305 or AES-GCM, with X25519 or P-256 key exchange. See Connection settings.

Your password

The program asks for your pastes password the first time you send, and keeps it in memory only, until you exit. It is never written to disk, exported or logged. Changing the server's host or port logs you out, so the password is never sent to a different server.

Speed

Setting up an encrypted connection is hard work for a Pentium-class processor. At start-up the program connects once in the background, which takes a couple of seconds; after that, a paste takes about half a second. See Connect at start-up to warm up the encryption code in Connection settings.
